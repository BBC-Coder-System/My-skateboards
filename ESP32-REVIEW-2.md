# ESP32 smart board: "Is this the best design?" (research round 2, 2026-10-10)

Three researchers (prior-art scout, alternative architect, red team) searched real projects and compared alternatives against ESP32-REVIEW.md. Nothing was tested on hardware.

## Answer
Not proven best. Two of three (alternative architect, red team) rank a different audio path first; the prior-art scout found no proven simpler design and would keep the current one with extra test gates. All three agree on: add a wheel hall sensor for the brake light; nobody has built the exact phone -> ESP32 -> transmitter -> speakers relay before; stock WLED sync is not a drop-in.

## The two candidates
| | Current (baseline): music through the board | Option D: music straight to the speakers, beat node at the speaker |
|---|---|---|
| Music path | iPhone -> ESP32 under deck -> DAC -> UGREEN -> TWS speakers on rider (2 extra Bluetooth hops through deck and body) | iPhone -> speakers, as today |
| If the board fails | music stops | only the light sync stops |
| Light sync | best possible: clean digital audio, 250 ms lookahead; delay offset can drift 50-100 ms between sessions (SBC) | mic at the speaker grille hears the real sound: 25-40 ms raw lag, ~0 on steady beats via tempo prediction; no calibration, no drift |
| Weak points | UGREEN + TWS unproven, start-up order, iOS BLE/A2DP connect order, I2S clock drift, more firmware | mic hears wind/traffic/voices (weaker on quiet/complex music), belt-to-deck radio through the body unmeasured, a third thing to charge |
| Extra parts | PCM5102 + UGREEN + cables | belt node: ESP32-C3 (XIAO or SuperMini) + INMP441 mic + small LiPo + tiny case (est. 300-500 THB) |
| Score (alt-architect) | 26/45 | 35/45 |

## Agreed for either design
- Wheel hall sensor (A3144/US5881) + 2-4 magnets in a wheel: real speed, clean brake detection, true "stopped" state (est. 30-60 THB). IMU stays for airtime/carve and confirmation.
- IP65-coated strip inside the aluminium channel (or sealed channel ends), conformal coat, glands; no riding on wet roads.
- Brake always overrides effects on the rear 20 LEDs; no red/blue police alternation while moving (strobes otherwise allowed per user).
- Bank: screwed pouch/bracket, take it along when parked; never leave it in sun or a car.
- Keep the WROVER on the board, so the other audio path can be added later without a new board.
- If baseline: desk gates for BLE-first-then-audio connect/reconnect (esp-idf #6557), I2S clock-drift handling (#3407), UGREEN with TWS pair, a 30-minute ride with the iPhone in a pocket (no dropouts, delay stable within 20 ms over 5 reconnects).
- If D: day-1 test with stock WLED-MM (ESP32 + INMP441 at the speaker as access point, second ESP32 receiving), then a night ride; custom ESP-NOW frames for the real build; board stays in Wi-Fi STA mode with BLE (coexistence rule), OTA turns BLE off.

## Main recommendation (Claude, combining the three)
Test both cheaply before committing: the extra parts for each are cheap (baseline: PCM5102 + UGREEN about 290 THB; D: ESP32-C3 + INMP441 + LiPo about 300-500 THB). Build the shared core (WROVER, strip, channel, shifter, IMU, hall sensor, bank, box), run D's stock-WLED test and the baseline's UGREEN + TWS test on the desk and on one night ride, then keep the winner. If only one is tried, try D first: it keeps the music as reliable as today.

Detailed reports: research summaries appended below.

## prior-art-scout
prior-art-scout: no proven simpler path meeting all requirements. Nobody built the full iPhone -> ESP32 sink -> DAC -> transmitter -> TWS chain; board half has precedent (Kolcha/cmu-esp32: A2DP sink + FFT + WS2812 RMT + BLE GATT on one ESP32). Only widely proven sound-reactive path is a mic (WLED/WLED-MM + INMP441). Mic-at-speaker node plausible but no wearable precedent, no wind-noise data, stock WLED ESP-NOW sync not proven (custom frames needed). Brake: add wheel hall sensor (accelerometer-only brake lights false-trigger: Lumos beta, Magicshine SeeMee oversensitive, Shredlights must be level; longboardLight1 uses hall + IMU).
Findings: WLED forum 6328 (A2DP -> PCM5102 + UART to WLED, 2 ESP32s, "works out of the box"); esp-idf #6557 (iOS couldn't start A2DP while BLE up; fixed late 2022; test BLE-first then audio + reconnect); esp-idf #3407 (I2S clock 44642 vs 44100 Hz on WROVER: APLL/ring buffer/fill-level control); two-ESP32 relay source side unproven (esp32.com, arduino-esp32 #11244); no consumer receive-and-retransmit gadget; TWS: pair to master only; transmitters may give "double mono"; no UGREEN 60300 + TWS reports; KCX_BT_EMITTER not universal; no commercial skate kit with BT-audio-driven lights; FastLED RMT can disrupt BT audio interrupts (use I2S1 DMA).
Suggested: desk gate BLE-first then A2DP connect/reconnect; firmware handles clock drift; optional hall sensor; second ESP32 transmitter not an easy fallback.

## alt-architect
alt-architect: current design NOT best. #1 = D (iPhone -> TWS speakers directly; belt beat node XIAO ESP32-C3 + INMP441 + 500 mAh LiPo at speaker grille -> ESP-NOW 64-byte frames 50-100 Hz -> board). Baseline #2 (Plan B on same WROVER).
Scores (sum): Baseline 26; A receiver module + WLED-MM 20 (lights 150-250 ms AHEAD of speakers, WLED can't delay); B two ESP32s 25; C relay gadget dead (no consumer product, only patent US10368376B2); D 35; D-alt Auracast dead (iPhone can't be Auracast source); E AudioKit/LyraT 20; F baseline + KCX_BT_EMITTER 24 (no TH listing, speaker compatibility issues).
D wins: music as reliable as today; no calibration/no drift; simpler (no DAC/UGREEN/hum/ritual/A2DP). D weak points: mic analysis weaker (traffic/voice/wind) -> adaptive noise floor, gate to ride scene/free-run tempo; wind in bass -> INMP441 in closed foam-lined cup pressed on grille, fixed to strap; no 250 ms lookahead (tempo prediction instead); 3 things to charge; belt-to-deck ESP-NOW through body unmeasured (hobbyist 75-byte FFT frames 50 Hz "works well, occasional missed messages"); coexistence: ESP-NOW RX + BLE stable only in STA mode, SoftAP + BLE unstable -> board stays STA, OTA mode turns BLE off; write custom ESP-NOW frames (WLED ESP-NOW sync shaky, UDP sync needs shared AP + lag); brake/ride scene independent of node.
Build 1: music iPhone -> TWS; node mic 16-22 kHz, AGC, FFT, spectral flux + bass env, tempo/phase lock, frames with seq numbers + beat phase timestamps; board WROVER (Plan B open), BLE GATT remote, ESP-NOW RX STA, LEDs I2S/RMT, ride scene, brake IMU + hall sensor; all strip/power/box/safety decisions stay. Day-1 de-risk: WLED-MM AudioReactive on ESP32 + INMP441 at the speaker driving desk LEDs, then short ride with phone filming; if not good enough -> baseline.
Parts: REMOVE PCM5102, UGREEN, 3.5 mm cable, USB-A breakout for TX, isolator, in-box calibration mic. ADD hall sensor A3144/US5881 + 2 neodymium magnets + 3-pin lead + 10k pull-up on GPIO4 (30-60 THB); belt node: XIAO ESP32-C3 (built-in LiPo charger, 200-300 THB) or C3 SuperMini + TP4056 (120-150), INMP441 (60-100), 500-1000 mAh protected LiPo (80-150), slide switch + 50x30x20 case + foam cup + clip (60-120). Net +0 to +300 THB -> ~2,100-2,800 total. TH prices for XIAO/INMP441 not confirmed.
Firmware effort lower than baseline. Second choice: baseline if best sync wanted and music may depend on board; B only if UGREEN fails.

## red-team
red-team verdict: NOT the best. SWITCH music/sync architecture, keep most hardware.
Ranked risks: (1) music through the board = fragile (two BT hops through deck + body, body blocks 15-20 dB at 2.4 GHz; any crash = silence) HIGH/HIGH; (2) UGREEN 60300 SBC only, TWS unverified, SBC delay drifts 50-100 ms per session (AirPods 215->155 ms over 20-30 min) MED-HIGH/HIGH; (3) IMU-only brake will disappoint (foot brake 0.1-0.3 g vs road vibration +-1-2 g, tilt leaks gravity; accelerometer bike lights false-trigger) -> FIX: hall sensor on truck + 2-4 magnets in a wheel = real wheel speed, braking = speed falling, ~100 ms, 30-60 THB (US5881/DRV5032 at 3.3 V); keep IMU for airtime/carve; (4) start-up ritual + silent failures (iPhone grabs speakers directly, board can't detect); (5) firmware effort 2-4 weeks, only Claude maintains; A2DP stutters during BLE activity (ESP-FAQ); (6) water/grit in rainy season: IP65 strip inside channel or sealed end caps, glands, conformal coat, no wet roads; (7) police red/blue while riding: Thai Motor Vehicle Act s.12/60 fines for blue/blinking lights on vehicles; brake overrides rear 20 LEDs, no red/blue police pattern while moving, app warning; (8) bails/theft: screwed pouch/bracket, skid strips, tether; (9) heat: bank out of sun; (10) 74AHCT125 wait low risk.
VERDICT: option D for build 1: iPhone -> TWS speakers directly (as today, zero new risk to music); belt "beat node" XIAO ESP32-C3 + INMP441 + 500 mAh LiPo (est. 300-400 THB) at the speaker grille sends ~64-byte beat/band frames to the board (Wi-Fi/ESP-NOW); board keeps WROVER, LEDs, IMU, BLE remote, ride scene, brake; drops PCM5102, UGREEN, hum fixes, delay calibration. Mic hears real speaker output -> no drift, nothing to calibrate; raw lag ~25-40 ms, tempo prediction -> ~0 ms on steady beats. Costs: dirtier mic signal (wind/traffic/voice), third thing to charge, lose 250 ms lookahead; brake/ride scene never depend on the node. De-risk: WLED-MM + INMP441 UDP Sound Sync Send -> second WLED Receive (documented feature), test in riding layout (node soft-AP, board station), ride test. Plan B: baseline A2DP later on the same WROVER (buy/test UGREEN with speakers first).
Sources: arxiv 2006.06822; Nordic devzone 122227; esk8 forum; UGREEN CM523 retailer specs; outeraudio latency; ESP-FAQ coexistence; road.cc CatEye Kinetic; nationthailand 40044254; mm.kno.wled.ge soundreactive sync; kno.wled.ge audio-reactive; WLED discourse 6330; github st00p/HamsterTach.

ADDITIONS (second hand-back): TWS guidance: transmitter pairs with the master only, many speakers refuse TWS if a source is already linked. Hall sensor alternative A3144 + 1-2 magnets (30-50 THB). Coexistence: ESP-NOW RX with BLE stable only in STA mode (SoftAP + BLE unstable) -> belt unit must be AP/sender; board OTA mode turns BLE off first. Strobes can trigger photosensitivity; keep rear 20 LEDs steady tail/brake that strobes cannot override. If the user keeps A2DP relay: gate = 30-min ride with iPhone in pocket + speakers on belt: no audible dropouts, UGREEN stereo works, delay stable within 20 ms over 5 reconnects; else switch to D. Extra sources: outeraudio TWS pairing; ESP-IDF coexist guide; mm.kno.wled.ge/WLEDSR/UDP-Sound-Sync.

THIRD HAND-BACK additions: prior-art-scout found NO finished build of phone->ESP32->transmitter->speakers relay; ESP32 classic BT TX only ~+9 dBm; I2S clock drift (esp-idf #3407, 44642 vs 44100 Hz, needs APLL/ring buffer); esp-idf #6557 iOS couldn't start A2DP while BLE link up (fixed late 2022, test order); forum: such transmitters give "double mono" at best with TWS; brake-light products: Magicshine SeeMee "oversensitive", Lumos brake feature beta/off by default; prior art longboardLight1 uses wheel hall sensor + IMU; ESP-NOW up to +20 dBm; WLED sync over ESP-NOW not proven -> belt node as AP with WLED-MM UDP sync for the day-1 test. Verdict "adjust, close to a switch": D for build 1, WROVER kept for Plan B, hall sensor main brake input, IP65 strip in channel, no red/blue while moving. If D fails the night ride, go back to baseline with UGREEN+TWS and dropout tests as hard pass/fail before mounting.
